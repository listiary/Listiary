We are performing basic integration testing here.
Unit-testing is a different layer.
UI testing in different browsers and resolutions is a different layer.
This protocol is for fast and dirty testing, so we can answer if everything looks like working properly - not trying to catch every bug.
----------------------------------------------------------------------------------------------------------------------------------------
1. Page loads: Open the demo URL successfully.
2. Source inspection: Check the browser's developer tools for visible errors, particularly in the Console and Network panels.
3. Desktop appearance: Verify that the page renders and looks reasonable in the current browser.
4. Mobile appearance: Use the inspector's device emulation, switch to the mobile layout, and verify that the page still renders and looks reasonable.
The goal is to catch obvious integration failures quickly, not to prove the absence of bugs.
